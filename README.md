# Clinic Database System

Учебный проект реляционной базы данных поликлиники на PostgreSQL. Схема охватывает пациентов и электронные медицинские карты, расписание приёмов, услуги, сотрудников и склад лекарств. Генератор на Python/Faker создаёт синтетические данные для знакомства со схемой и SQL.

## Что реализовано

- Таблицы и связи для пациентов, ЭМК, ограничений, назначений и заключений.
- Расписание: сотрудники, корпуса, кабинеты, слоты и обращения.
- История должностей и зарплат; лекарства, поставщики, склад и история его движения.
- Первичные и внешние ключи, ограничения `UNIQUE`, `NOT NULL` и `CHECK`.
- Одиночные и составные индексы, PL/pgSQL-функция и триггеры для обновления `updated_at`.
- Генерация связанных данных: справочники, основные таблицы, затем таблицы со связями. Данные сохраняются в SQL-файл с командами `INSERT`.

## Требования

- PostgreSQL 16 и клиентские утилиты `createdb`, `psql`.
- Доступ к запущенному серверу PostgreSQL и роль с правом создать базу данных.
- Python 3.10+ и Faker — только для повторной генерации данных. Для загрузки готового `hospital_data.sql` Python не нужен.

Команды ниже выполняются из корня репозитория. В примере используются сервер `localhost`, роль `postgres` и новая база `clinic_demo`; подставьте параметры своего сервера. Пароль, если он требуется, утилиты запросят отдельно.

## Загрузка готовых данных

```bash
git clone https://github.com/lioiioiioil/Hospital-Sql.git
cd Hospital-Sql

# Создать отдельную пустую базу для учебного проекта.
createdb -h localhost -U postgres clinic_demo

# Создать схему. Имя файла содержит пробел, поэтому нужны кавычки.
psql -h localhost -U postgres -d clinic_demo \
  -v ON_ERROR_STOP=1 --single-transaction -f "Hospital new.sql"

# Загрузить демонстрационные данные.
psql -h localhost -U postgres -d clinic_demo \
  -v ON_ERROR_STOP=1 --single-transaction -f hospital_data.sql
```

Схема рассчитана на пустую базу: повторный запуск `Hospital new.sql` в той же базе приведёт к ошибкам создания уже существующих объектов. `ON_ERROR_STOP` останавливает выполнение при первой SQL-ошибке, а `--single-transaction` выполняет каждый файл целиком в одной транзакции.

Для проверки результата:

```bash
psql -h localhost -U postgres -d clinic_demo -c '\dt'
psql -h localhost -U postgres -d clinic_demo \
  -c 'SELECT COUNT(*) AS patients_count FROM patients;'
psql -h localhost -U postgres -d clinic_demo \
  -c 'SELECT COUNT(*) AS slots_count FROM slots;'
```

## Повторная генерация данных

Этот шаг необязателен. Генератор использует случайные значения и текущую дату, поэтому при повторном запуске данные будут отличаться.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python script.py
```

`script.py` записывает файл `hospital_data.sql` в текущий каталог и **перезаписывает существующий файл**. Если нужен исходный набор, сохраните его копию перед генерацией. Скрипт создаёт объёмный набор данных; генерация может занять время.

Сгенерированный SQL начинается с `TRUNCATE ... RESTART IDENTITY CASCADE`: его загрузка очищает таблицы проекта и сбрасывает их последовательности. Используйте отдельную учебную базу `clinic_demo`. Для загрузки нового набора повторите команду `psql ... -f hospital_data.sql` из раздела выше.
